# ui

**Layer 3 · Front end**

The interface: the dockable layout, menus, palettes, Attribute and Object Managers, the UV Editor panel, and the theme.

## Purpose

Draws everything around and on top of the viewports with egui and egui_dock: menu bar, command palette, mode palette, the Attribute Manager (top right) and Object Manager (below it), the Coordinates panel, status bar and the calm dark theme. Hands viewport input to `tools` and carries out the commands they return. See DESIGN.md §5.

## Must never

- Change the scene except by executing commands
- Hold modelling logic: that belongs in `tools`, `mesh` or `scene`
- Use proprietary icons or artwork copied from other software

## Depends on

`tools` (the camera), `scene` (the document), `mesh` (primitive setting limits; `config` planned). Outside libraries: `glam` (maths), `egui` and `egui_dock` (interface and docking), `serde` (saving the layout).

## Status

The window's layout is in place:

- **`Workbench`**: draws the whole window each frame and returns actions (`Quit`) for the app. Takes the app's name in `AppInfo`, so this crate never names the app.
- **Panels** (`Panel`): Viewport, Attributes, Objects, Coordinates, docked with egui_dock. Not closeable, not floating. The standard layout (`layout::default_layout`) puts Attributes top right, Objects below, Coordinates under the viewport; a damaged saved layout is replaced with a status-bar note.
- **Menu bar** in the design's order (File, Edit, Create, Modes, Select, Tools, Mesh, UV, View, Window, Help), with the layout tabs (Standard; Modelling and UV Edit greyed out) on the right. Working: File → Quit (Ctrl+Q), Modes, View → Reset view, Grid lines (three levels) and Reset panel layout, Window → Accent colour, Help → About. Everything else is listed greyed out with the phase that brings it.
- **Panel menu lines** (`panels::menu_line`): Attributes (Mode, Edit, Units) and Objects (Edit, View, Object).
- **Palettes** (`palette`): the command palette (top, all commands greyed out for now) and the mode palette (left; Model, Object, Points, Edges, Polygons and UV can be picked, and the status bar says which is active).
- **Theme** (`theme`): the darker studio look (decision 0014), applied at startup by the app: colours, the viewport backdrop, the Inter font (Regular and SemiBold), text sizes, spacing, frames and the docked tabs' style. **`Accent`**: red (standard), blue, marine green, plum, olive or petrol blue, each with fill, light and soft shades; `set_accent` switches it app-wide and `accent` reads it back from egui's memory. Tests check every text colour is readable (WCAG 4.5:1), every accent's marks are visible, and neighbouring areas stay gently close.
- **Layout** (`layout`): besides the standard arrangement, `hide_viewport_tab` hides the viewport's tab each frame (its menu line replaces it) unless another panel shares its group.
- **Icons** (`icons`): 32 original icons (shapes, groups, eyes and tools) drawn with egui shapes on a 24 × 24 grid.
- **Viewport** (`viewport`): its own menu line (`viewport::chrome`: View, Cameras, Display, Options, Panel, and buttons to drag for pan, zoom and orbit), the image from a `ViewportRenderer` sized in physical pixels, overlays (view and camera names, axis marker, grid spacing) and the navigation controls picker (`viewport::picker`) in the bottom-right corner. Without a GPU (`NoRenderer`), it shows the backdrop and says why. Turns drags and wheel turns into `tools::Navigator` moves using the chosen `NavigationSettings` (the drag kind is fixed when the drag starts) and sets the mouse cursor while navigating. `ViewOptions` (the `GridDetail` level: 1 m, 50 cm or 10 cm; navigation settings; four views) is saved by the app between sessions; an old `fine_grid` setting is read and turned into the 10 cm level by `ViewOptions::migrated`. While the mouse hovers over the image, the panel asks the renderer what is under it (`ViewportRenderer::pick`, never waiting; a resting mouse asks nothing new); orbiting then turns around that surface point, and zooming moves towards it (or the ground, or along the line of sight). A ring marks the pivot while orbiting or drag-zooming. Frame all (`H`) and frame selected (`F`), from the keys or the View menus, glide the view (`GLIDE_SECONDS`) until the boxes from `SceneSummary` fit (the selection, else everything shown, else `DEFAULT_FRAME`, a 1 m box at the origin); taking hold of the view stops a glide.
- **Four views** (`viewport`): the panel holds four views (perspective, top, front, right; `VIEW_COUNT`), each with its own camera, drag, glide and picking answer, shown one at a time or in a 2 × 2 layout (`ViewOptions::four_views`, saved). `F1`–`F4` show one (`VIEW_KEYS`), `F5` all four (`FOUR_VIEWS_KEY`), and a middle click switches. The last view clicked is active (an accent outline); the menu line, its buttons, Reset view and framing act on it, and `camera()`/`navigator()` return it. Cameras changes the active view's kind; Panel → Four views and the square header button switch the layout. `ViewportView` carries the view's `slot`, `flat_height` and `grid_plane`; only the view under the mouse asks what is there. In four-view mode each image is labelled with its view, e.g. "3D viewport (Top)".
- **Object Manager** (`objects`): the scene tree with fold arrows, kind icons, selected names in the accent colour (`AccentColors::text`, readable on the row's tint) and an eye per row. Click, Ctrl+click and Shift+click select; double-click renames in place (Enter or clicking away keeps the name, Esc cancels); dragging onto a row nests, onto its edge reorders, below the rows moves to the top level; right-click opens the object commands. It hands back `DocRequest`s (a command, undo or redo) for the workbench to carry out; only the selection is changed directly. Its menu line (Edit, View, Object) and the main Edit and Create menus share the same entries.
- **Document** (`Workbench`): owns the `scene::Document`, carries out requests from the panel, menus, palette and keys (Ctrl+Z, Ctrl+Y, Ctrl+Shift+Z, Delete, Backspace, Esc, Alt+G, Shift+G; not while typing or renaming; Esc closes an open menu first), and reports undo, redo and refusals in the status bar, which also counts the selection. The command palette's undo, redo, shape and group buttons work, and the Create menu lists every primitive and Group. **Shape list** (`shape_picker`): `B` (`SHAPE_LIST_KEY`) opens a list of primitives by the mouse; `B` again moves down, `Shift + B` or the arrow keys move, `Enter` or `Space` creates, `Esc` or a click elsewhere closes; clicking an entry creates it. Not while typing. The Attributes panel names the selection.
- **Attribute Manager** (`attributes`): for one selected object, a heading (icon, name, kind), Basic (Name, Visible) and, for primitives, Shape: the kind's settings (`attributes::fields`) as drag-or-type fields with step arrows (`attributes::stepper`: one step per click, ten with Shift; lengths in the chosen `Units`, metres or centimetres, switched beside the Shape title or in the Units menu and saved by the app), counts and switches, with their limits. Changes go out as `SetPrimitive` commands through `DocRequest::RunMerging`, keyed by a gesture count so one drag, typed value or click is one undo step. Its menu line: Mode (object settings; tool settings later) and Edit (Copy settings, Paste settings to the selected shapes of the same kind; the same entries, `attributes::settings_entries`, are in the Object Manager's right-click menu, sharing one clipboard) and Units. Several selected objects are counted.
- **Scene drawing** (`drawing`): `DrawingCache` turns the document into a `SceneSummary` (the `SceneDrawing` of shown objects with a shape, each a mesh, world transform and selected flag, plus the boxes `H` and `F` frame), rebuilding only when the scene revision or selection changes and reusing each primitive's mesh until its settings change. `ViewportView::scene` hands the drawing to the renderer; its `version` says when it changed.
- **Placeholders**: the other panels say what will appear in them and when.

Tests run the real interface without a window (egui_kittest): every tab and menu is present and in order, Attributes sit above Objects, the viewport has its menu line instead of a tab, Ctrl+Q and File → Quit quit, modes can be picked, unbuilt commands cannot be clicked, real drags and wheel turns navigate in each scheme, the header buttons navigate when dragged, F1–F5, middle clicks, the Cameras and Panel menus and the header button switch views, clicking a view makes it active, flat views pan and zoom but never orbit, the picker lists and switches schemes, the accent can be changed and is restored, layouts are reset and broken ones explained, and the About box opens. `attribute_tests` covers the Attribute Manager (fields per kind, dragging as one undo step, limits, typing a value, step arrows and Shift, units, end settings, switches, the name field, Visible, copy and paste). `shape_picker_tests` covers the B shape list (opening, moving both ways, Enter, Space, Esc, clicking, not while typing). `object_tests` covers the Object Manager: selecting, folding, creating, deleting (keys and right-click), undo and redo (keys, menu, palette), hiding through groups, grouping, renaming (including Esc, refused empty names and keys going to the name), dragging to nest, reorder and un-nest, refusing to drop a group inside itself, framing the selection, and copying and pasting settings from the right-click menu.
