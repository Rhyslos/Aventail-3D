# ui

**Layer 3 · Front end**

The interface: the dockable layout, menus, palettes, Attributes and Objects panels, the UV Editor panel, and the theme.

## Purpose

Draws everything around and on top of the viewports with egui and egui_dock: menu bar, command palette, mode palette, the Attributes panel (top right) and Objects panel (below it), the Coordinates panel, status bar and the calm dark theme. Hands viewport input to `tools` and carries out the commands they return. See DESIGN.md §5.

## Must never

- Change the scene except by executing commands
- Hold modelling logic: that belongs in `tools`, `mesh` or `scene`
- Use proprietary icons or artwork copied from other software

## Depends on

`tools` (the camera), `scene` (the document), `paint` (texture sets and mixing them), `mesh` (primitive setting limits; `config` planned), `words` (the language layer, re-exported as `text`). Outside libraries: `glam` (maths), `egui` and `egui_dock` (interface and docking), `serde` (saving the layout).

The window's layout is in place:

- **`Workbench`**: draws the whole window each frame and returns actions (`Quit`) for the app. Takes the app's name in `AppInfo`, so this crate never names the app.
- **Panels** (`Panel`): Viewport, Attributes, Objects, Coordinates, Edit layers, docked with egui_dock. Not closeable, not floating. The standard layout (`layout::default_layout`) puts Attributes top right, Objects below, Coordinates under the viewport; a damaged saved layout is replaced with a status-bar note. Edit layers is a tab beside Objects; a layout saved before it existed gets it added there (`Panel::ADDED_LATER`, `layout::add_later_panels`), and `layout::show_tab` brings a panel to the front. The modifiers palette is hidden in the UV mode, and otherwise drawn on the right of the view beside Attributes (`layout::modifiers_palette_host`: the viewport, or the UV Editor in UV Edit; `PanelViewer::modifiers_palette`, [decision 0176](../../docs/decisions/0176-modifiers-palette-beside-attributes.md)).
- **Menu bar** in the design's order (File, Edit, Create, Modes, Select, Tools, Mesh, UV, View, Window, Help), with the project's name (and an Unsaved badge in the accent colour) and the layout tabs (Standard; Modelling and UV Edit greyed out) on the right. Working: File (New, Open, Open recent, Save, Save As, and Quit, which has no key on purpose), Modes, View → Reset view, Grid lines (three levels) and Reset panel layout, Edit → Settings…, Help → Add a heavy test shape (a 3-million-polygon ball as one undo step, `Workbench::add_heavy_test_shape`) and Help → About. Everything else is listed greyed out with the phase that brings it.
- **Panel menu lines** (`panels::menu_line`): Attributes (Mode, Edit, Units) and Objects (Edit, View, Object).
- **Palettes** (`palette`): the command palette (top: undo, redo, the select tool button showing the active `SelectTool`, shapes and group work; the rest greyed out) and the mode palette (left; Model, Object, Points, Edges, Polygons and UV can be picked, and the status bar says which is active).
- **Theme** (`theme`): the darker studio look (decision 0014), applied at startup by the app: colours, the viewport backdrop, the Inter font (Regular and SemiBold), text sizes, spacing, frames and the docked tabs' style. **`Accent`**: red (standard), blue, marine green, plum, olive or petrol blue, each with fill, light and soft shades; `set_accent` switches it app-wide and `accent` reads it back from egui's memory. Tests check every text colour is readable (WCAG 4.5:1), every accent's marks are visible, and neighbouring areas stay gently close.
- **Windows** (`dialog`, [decision 0087](../../docs/decisions/0087-one-look-for-every-window.md)): the parts every window is built from. `Dialog::new(title, width)` (`.body_height`, `.modal()` for questions, `.id`) shows a frameless window whose closure gets a `DialogUi` and calls `header(closable, extra)` (title, anything beside it, the × labelled "Close window"), then `body` or `sections(chosen, &[Section], note, add)` (a side list with badges On/Off and the chosen section in a scroll area), then `footer(note, buttons)` or `footer_with(left, buttons)`. Inside: `heading`, `heading_with_pill`, `help`, `divider`, `row(name, control)` (names in a `NAME_WIDTH` column), `segmented` (two to four choices), `drop_down` with `drop_down_entry` (name and a hint on the right), `chip`, `locked` (a value a preset fixes), `place` (a path with a folder), `tiles` (numbers with words), `main_button` (accent) and `plain_button`; `enter_or_escape` takes Enter and Esc for a window's buttons when nothing is being typed (the workbench's Esc-to-deselect waits while a window is open, `Workbench::window_open`). Menus: `menu_config`/`menu_style` (roomier rows) on every menu bar, and `menu(ui, title, add)` keeps each menu at least `MENU_WIDTH` wide. Export, Settings, Check for baking, About and the three questions (unsaved changes, dissolving across a corner, recovering backup copies) use them; the Keys window keeps its own resizable frame. When the system's file window can't open, the app calls `Workbench::file_window_missing` with a `FilePurpose` (save the project, open, import, export, export a kit, a game project folder) and the **path window** (`workbench/path_entry`, [decision 0164](../../docs/decisions/0164-interface-fixes-from-the-phase-10-testers.md)) asks for the path: checked as typed (`checked`: `~` for home, the extension added, the folder must exist), then sent on as the action with its path filled in.
- **Words** (`text`, decisions [0132](../../docs/decisions/0132-one-language-layer.md) and [0134](../../docs/decisions/0134-shared-language-crate.md)): every text the interface shows goes through one layer, which lives in the `words` crate so `scene`, `mesh` and `fileio` use it too; `text` re-exports it and the crate root re-exports its macros, so the interface writes `crate::text::tr("…")` for plain text, `crate::trf!("{} selected", n)` in place of `format!` (`{}`, `{:.N}` and braces only), and `crate::text!("…")` for text kept in a constant, shown with `tr(CONSTANT)`. English is the key and the one package, `crates/words/lang/en.txt`; `Package` and `use_package` take another language later. A test in `text_checks` reads the source of every crate that makes text (`ui`, `scene`, `mesh`, `fileio`, `app`, `tools`, `uv`, `config`; not `render`, whose texts are GPU debug names) and writes `words/lang/en.txt` and `words/lang/skipping.txt` (`UPDATE_LANG=1`); `skipping.txt` is empty, and any new text that skips the layer fails the test, which lists it. The test counts text that reads as words (two letters or more, and a space or a capital first letter), leaving out ids, comparisons, Debug output and tests; single lowercase words ("polygon", "on") go through `tr` too, though the test can't tell them from ids.

## Where the code is

The biggest modules are split into files by job, each opening with a note saying what it holds:

- **`workbench`** (`workbench.rs`: the window's state, `Workbench::new` and `show`, the frame's order): `autosaving` (autosave and recovery), `files` (title, saving, opening, "Save changes?"), `file_work` (a save or export the app does on another thread, decision 0163: `FileWork`, `file_work_started`, the status bar's note and turning wheel, `hold_file_actions` keeping back another save, export, open, import or new project meanwhile, `saved_at` for a save reported at the revision it copied), `layouts` (the standard and UV Edit layouts and their tabs), `preferences` (the Settings window, undo memory, units, accent, view options), `requests` (document and mode keys, carrying out requests), `bars` (menu bar and status bar), `mesh_menu`, `uv_menu`, `tabs` (each docked panel's contents) and `heavy_shape` (Help → Developer → Add a heavy test shape), beside the feature files listed above. `exporting` keeps the Export window's contents in `exporting/window`.
- **`viewport`** (`viewport.rs`: `ViewportPanel`, its state and `show`): `options` (`ViewOptions`, grid detail, surface, shading, symmetry, the grid and checker images), `renderer` (`ViewportView`, picking questions and answers, the `ViewportRenderer` trait, `NoRenderer`), `view` (one view: camera, navigation drag, glide, framing) and `input` (Ctrl + wheel, the view keys, framing keys, asking what is under the mouse), beside `chrome`, `dice`, `gizmo`, `look`, `mirror_plane`, `picker`, `select` and `tool_drag`.
- **`attributes`** (`attributes.rs`: `AttributesPanel`, its menus and `show`): `object_rows` (heading, name, shape settings, collision, smoothing), `mesh_check` (the Mesh section and its background check), `edits` (the Edits section and an opened edit), `last_edit` (the last edit's settings and Change it), `tool_section` (the Tool section and the tools' kept settings) and `tool_rows` (the settings rows both share), beside `fields`, `materials` and `stepper`.
- **`icons`** (`icons.rs`: the `Icon` list, `ALL`, `paint` and `shapes`, which sends each icon to the file that draws it): `pen` (the drawing pen on the 24 × 24 grid), `general`, `primitives`, `tools`, `modelling` and `uv`, one family of icons each.
- **`uv_editor`** (`uv_editor.rs`: `UvEditor`, its state, `show` and the gizmo's use): `shape` (one object's UVs as drawn and picked), `navigation` (panning, zooming, framing), `painting` (the texture square, polygons, seams, selection, stretch colours), `picking` (clicks, box selection, whole islands) `menus` (the Texture and Trim menus, the texel density line) and `brushing` (the paint brush in Paint mode), beside `checking`, `explain`, `gizmo` and `snapshots`.
