# app

**Layer 4 · App**

The application itself: wires every crate together, opens the window and owns the frame loop.

## Purpose

Starts the program: loads settings, opens the window, hands each frame to `ui`, connects the renderer, shows file dialogs and calls `fileio`. Also home to `branding.rs`, the **only** place in code that names the app (see RENAMING.md).

## Must never

- Contain feature logic: every feature belongs in a lower crate
- Name the app anywhere except through `branding`

## Depends on

`ui`, `render`, `fileio`, `scene`, `paint` (painted textures to upload) (for the backup copy's document), `words` (the language layer: dialog titles, start-up steps and messages go through it, [decision 0134](../../docs/decisions/0134-shared-language-crate.md)) (every other app crate planned). Outside libraries: `eframe` (window and frame loop), `windows-sys` and `raw-window-handle` (Windows only), `rfd` (native Open and Save dialogs; the desktop portal on Linux), `sys-locale` (the system language, so the Keys window draws the right keyboard; decision 0061).

## Status

- **Painting** ([decision 0178](../../docs/decisions/0178-textures-on-materials.md)): `gpu::GpuViewport::upload_painted` uploads each texture set's mixed image (`ui::PaintedTexture`) when the Painted surface is shown, only the tiles that aren't the same tiles as last time; `project::import_paint_image` asks for a picture (or takes a typed path, `FilePurpose::PaintImage`) and hands it to `Workbench::import_paint_image`. The person's brushes are kept between sessions (`BRUSHES_KEY`, decision 0185). `project::choose_stencil` reads the picture projection paints (decision 0186). `tablet` (Windows: Wintab loaded at run time through `wintab_lite` and `libloading`, its packet queue read every frame for pressure, tilt and the eraser end, handed to `Workbench::set_tablet_pen`; [decision 0184](../../docs/decisions/0184-brush-feel.md)). `project::import_palette` and `export_palette` read and write GIMP palette files (at most 1 MB read; typed paths through `FilePurpose::ImportPalette` and `ExportPalette`; [decision 0183](../../docs/decisions/0183-colour.md)).

- **`backups`** ([decision 0036](../../docs/decisions/0036-autosave.md)): `folder()` is where backup copies go (`%LOCALAPPDATA%\<APP_ID>\autosave` on Windows, `eframe::storage_dir(APP_ID)/autosave` elsewhere). `Backups::start` offers what crashed runs left behind to the workbench (`offer_recovery`) and starts this run's `fileio::autosave::Session`; `write` writes the workbench's `Autosave` copy on another thread; `update` (each frame) reports a finished copy (`autosaved`, `autosave_failed`) and notes the open project; `restore` opens a copy, adopts it into this session and hands it to the workbench (`recovered`); `discard` deletes a leftover; `end` (on a normal close, `eframe::App::on_exit`) waits for a copy being written and deletes this run's folder. Tests: a crash and restore across two runs, discarding, a damaged copy, and no folder at all. Restoring marks the copy first (`autosave::mark_restoring`) and clears the mark afterwards, so a copy whose restore closed the app isn't offered again (decision 0045). `folder()` on a `Backups` gives this run's session folder, for the emergency copy; restoring an emergency copy says so ("Restored your work from the emergency copy saved as the app crashed (…)"). Tests also cover restoring an emergency copy and the wording.
- **`updates`** ([decision 0169](../../docs/decisions/0169-installer-and-updates.md)): `build_number` (`APP_BUILD`, set by the release workflow), `why_not` (only an installed, numbered Windows copy with the setting on updates itself), `parse_release` (GitHub's latest release: `build-N` tag, page, the `<APP_ID>-setup.exe` asset and its size), `look` (ask, compare, download into `folder()` as a `.part` kept only at the right size, forget older ones), `Curl` (the `Fetch` through the system's curl, no window, common failures said plainly), `Updater` (looks at once, while the splash screen waits for it in `window::Step::Updates`, and every 6 h after, on its own thread, until a build is ready; `Found::Downloading` and `progress` let the splash screen show the download, decision 0172; the first look reports `Found::Newer` and waits for `download`, and builds up to `set_quiet` are `Found::Skipped`, decision 0173). `window_updating` (in `window`) runs it: the splash screen's wait and question (`SplashUpdate`, `Updating::answer`), Update now closing the window to install, and the running app's offers and `PendingInstall` (the setup program and its quiet arguments, `/NOLAUNCH` after Later), set by `window` on the workbench's `InstallUpdate` and run by `window::run` once the window has closed. Tests use a fake internet (`Fetch`), and a fuzz test feeds random answers.
- **`build.rs`**: on Windows, puts the logo (`assets/icon.ico`) on the program file with `winresource` ([decision 0171](../../docs/decisions/0171-logo.md)); the window's own icon is `window::window_icon` (`assets/icon-256.png`).
- **`emergency`**: the emergency copy on a crash. `Emergency` is shared between the app and a panic hook (`install`, once, in `window::run`; it runs the usual hook first): it holds this run's backup folder (`set_folder`, once backups start; `forget` on a normal close) and a snapshot of the document (`keep`), behind a lock the hook only tries to take (`LOCK_TRIES` × `LOCK_PAUSE`, a tenth of a second; a broken lock is got past). `Snapshots::update`, after every frame, keeps a copy of the document (scene and selection, no history; shapes are shared) when it changed and has unsaved changes, at most every `SNAPSHOT_EVERY` (half a second; it returns when to look again so the app asks for a frame then), and clears it when nothing is unsaved. On a panic the hook writes the snapshot with `fileio::autosave::write_emergency_in` on a thread of its own, waiting at most `HOOK_WAIT` (10 s), one copy at a time; nothing in it can panic. Tests: writing and recovery finding it, nothing unsaved or nowhere to write, a held lock giving up quickly, a broken lock, one copy at a time, snapshot timing, and a real panic in a separate process (the test program runs its own ignored `panicking_child`).
- **`branding`**: the app's name, short name, settings ID, family and project file extension.
- **`cli`**: `--version` and `--help`; unknown options are explained (exit code 2).
- **`gpu`**: `GpuViewport` connects the `render` crate to the window's GPU device and registers its images with egui: one per view (`ViewportView::slot`), so the four-view layout shows four images. Passes flat views' height and grid plane on to the renderer. Keeps each object's mesh on the GPU ([decision 0035](../../docs/decisions/0035-heavy-meshes.md)): a mesh that is the same isn't touched, one whose points only moved is updated around them (`render::MeshGeometry::moved`), anything else is uploaded whole, and a heavy new one (50 000 polygons or more) is worked out on another thread while the view says so (`ViewportRenderer::preparing`). Each frame it places the objects (`mesh_draws`: edges in the accent when selected, plain while edited, a boolean's cutter as an outline only, its faces off and its edges never fading away, [decision 0135](../../docs/decisions/0135-live-booleans.md), clearer in the Shaded with wires and Wireframe looks, points in the Points mode; faces left out for Wireframe, [decision 0063](../../docs/decisions/0063-wireframe.md); cavity switched from `ViewportView::cavity`, [decision 0065](../../docs/decisions/0065-cavity.md); the surface from `ViewportView::surface`, with each object's texel density from its uploaded geometry for the Stretch view, `mesh_draws_showing`, [decision 0102](../../docs/decisions/0102-checker-and-stretch.md); the numbered checker's image made with `ui::grid_image` and given to the renderer when first shown and whenever `ViewportView::grid_colors` change, [decision 0107](../../docs/decisions/0107-numbered-checker.md)). Meshes are built shaded by angle while Automatic hard edges is on (`ViewportView::auto_hard_angle`, [decision 0064](../../docs/decisions/0064-automatic-hard-edges.md)): switching it rebuilds them all, and a move that turns an edge sharp or soft rebuilds a light shape at once, while a heavy one follows the move with its old shading and is reshaded on another thread ([decision 0066](../../docs/decisions/0066-clickable-axes.md)) and leaves out points and edges too dense to see from that view (`leave_out_dense`). A curve's line, handles and points (decision 0138) are overlay lines and dots (`CURVE_LINE`, `HANDLE_LINE`), and a curve's solid is never drawn as an edited mesh.
  It also turns the workbench's `ComponentOverlay` into a `render::Overlay` (`overlay_geometry`: plain points and lines in soft white, hovered ones larger and thicker in the accent colour, hovered polygons tinted; seams orange, edges where seams are preferred pale orange and where none may go blue, decision 0111) and uploads it when its version changes.
  Selected elements are drawn in the accent colour (larger points, thicker edges, tinted polygons); the hovered one in a lighter accent (`HOVER_LIFT`).
  Objects' edges follow the Edges switch (`mesh_draws_showing` with `ViewportView::show_edges`, [decision 0220](../../docs/decisions/0220-edges-switch.md)): drawn in light grey (`WIRE_LINE`) when on and always in Wireframe, left out when off; selected objects not being edited are marked `selected` and outlined `SELECTION_OUTLINE` pixels wide (wider with High contrast) in the accent colour.
- **`project`**: carries out the workbench's Save and Open actions: native dialogs (`rfd`, filtered to the app's project files, `.avtl` added if left out), `fileio::project::save`/`open`, and reporting back (`saved`, `save_failed`, `save_cancelled`, `opened`, `open_failed`). Saving and exporting come in halves: the dialogs (`where_to_save`, `export_path`, `kit_folder`), the work on a document (`save_work`, `export_work`, `export_into_work`, `kit_work`) and the report (`report_saved`, `report_exported`). A dialog that gives nothing back within `NO_WINDOW_WITHIN` (half a second) never opened (`asked`, `Asked::NoWindow`: on Linux, no file portal and no zenity); the workbench is then told with `file_window_missing` and asks for the path itself ([decision 0164](../../docs/decisions/0164-interface-fixes-from-the-phase-10-testers.md)).
- **`file_work`** ([decision 0163](../../docs/decisions/0163-saving-and-exporting-in-the-background.md)): `FileJobs` runs a save, export, export into the game project or kit export on another thread, on a copy of the document taken with `Scene::copy_with_results` (shapes shared, worked-out results kept); one at a time (`busy`; another is refused with `Workbench::file_work_refused`). `update` (each frame) reports finished work and says whether the window closes now (`AfterWork`): `close_when_done` keeps the window open while work runs, then closes it (asking again about changes after the window's close button, at once after File → Quit), staying open when the work failed. `finish` waits for it on `on_exit`. A save is reported at the revision it copied (`Workbench::saved_at`).
- **`cli`**: `--version`, `--help`, and a project path to open at start (as a file association will pass it); `--` ends the options, so a path may start with `-` ([decision 0045](../../docs/decisions/0045-limits-for-files.md)).
- **`platform`**: small fixes for one system. `keep_keyboard_focus` runs each frame; on Windows it hands the window the keyboard when it is active but nothing holds it (the cause of the error sound on key presses), using `windows-sys` — the one module allowed `unsafe` ([decision 0026](../../docs/decisions/0026-windows-keyboard-focus.md)). Elsewhere it does nothing. `use_parent_terminal`: on Windows the app is a window program (`windows_subsystem = "windows"` in `main.rs`, no console window), so for `--version`, `--help` and errors it borrows the terminal it was started from, if any ([decision 0170](../../docs/decisions/0170-windows-install-folder-and-no-console.md)); a window that can't open also says why in a message box.
- **`window`**: opens the window with eframe and wgpu. While starting (`Shell::Starting`, [decision 0079](../../docs/decisions/0079-splash-screen.md)) it shows `ui::splash` and runs one `Step` a frame (graphics, workbench, the project to open, backups), each named on screen while it works, for at least `SPLASH_AT_LEAST`; settings are read before the first frame (`Remembered`). Then (`Shell::Running`) it hands each frame to the `ui` workbench, carries out Quit, asks the workbench before the window's close button closes it with unsaved changes, keeps the title (project name; `●` and "(unsaved)" for unsaved changes) up to date, and saves the panel layout, view options, accent colour, units (metres or centimetres), undo memory limit, recent projects, autosave settings and the tool menu's look between sessions under the stable `APP_ID`. Carries out the workbench's `Autosave`, `Restore` and `DiscardBackups` actions through `backups`, installs the emergency copy's panic hook before the window opens and updates its snapshot after each frame (`emergency`), and asks for a repaint after any action so what it did (an opened or restored project) shows at once. A panic from a missing system library is caught and explained with an install hint. View options saved include the snapping settings, axis locks and world or object axes.
