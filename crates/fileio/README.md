# fileio

**Layer 2 · Services**

Everything that touches files: `.avtl` projects, OBJ and glTF import and export, the settings file.

## Purpose

Reads and writes the outside world's files: the versioned `.avtl` project format (DESIGN.md §8, decisions [0007](../../docs/decisions/0007-rhy-project-format.md) and [0010](../../docs/decisions/0010-avtl-file-extension.md)), OBJ and glTF for Substance Painter and Godot (with deterministic triangulation and MikkTSpace tangents), and the settings file described by `config`.

## Must never

- Trust a file: every reader checks sizes and counts before allocating, rejects bad input with a plain-language error, and gets a fuzz test
- Leave a half-written file: write to a temporary file, keep the previous save as a backup, then swap it in
- Write usernames or local paths into exported files
- Know about the GPU or UI

## Depends on

`scene`, `mesh`; `uv` and `config` planned. Outside libraries: `serde` and `postcard` (encoding), `zstd` (compression), `glam`.

## Status

**Projects** (`project`, decisions [0024](../../docs/decisions/0024-saving-projects.md) and [0031](../../docs/decisions/0031-project-format-version-2.md)):

- `to_bytes`/`from_bytes` and `save`/`open`. The file is a 20-byte header (`SIGNATURE` `AVTL`, `FORMAT_VERSION` 35, flags with bit 0 for zstd, the body's length) followed by the body: the file model (plain data separate from the scene's types) encoded with postcard and compressed with zstd. `project/v1.rs` holds the structures, generic over recorded operations (`ProjectFile<Op>`, `FileOperation`); version 1 uses `OperationV1` (moves), version 2 (`project/v2.rs`) `OperationV2` (moves, and points turned or scaled by a matrix, each with its anchors, `AnchorsV2`, every number checked on reading; [decision 0032](../../docs/decisions/0032-edits-find-their-points-again.md)). Version 3 (`project/v3.rs`, [decision 0038](../../docs/decisions/0038-extrude-and-inset.md)) stores version 2's operations as they were (`OperationV3::V2`), then extruded and inset polygons and extruded edges (distance checked, grouping, anchors; an edge must join two different points). Version 4 (`project/v4.rs`, [decision 0040](../../docs/decisions/0040-bevel.md)) wraps version 3's operations (`OperationV4::V3`) and adds bevelled edges and points (width and profile checked, rows brought within 1–64, profile within -1–1). Version 5 (`project/v5.rs`, [decision 0044](../../docs/decisions/0044-edits-that-hold.md)) keeps each recorded edit as an `EntryV5` (id, on/off, pinned, version 4's operation as it was, and `AnchorsMoreV5`: the structure fingerprint), through `FileOperation::entry_to_file`/`into_entry` (older versions number their edits 1, 2, 3… in order); and plain meshes' attribute layers beside the objects (`MeshLayersV5`, every value checked by `Mesh::set_attribute_values`; hard edges stay with the mesh). Version 6 (`project/v6.rs`, [decision 0047](../../docs/decisions/0047-loop-cut.md)) is version 5's file with `OperationV6`: version 4's operations as they were (`OperationV6::V4`) and loop cuts (the edge's two points must differ, the position must be a real number; cuts brought within 1–64, position within 0–1). Version 5's structures are generic over the operation (`EntryWith<Op>`, `ProjectWith<E>`), so a later version adds only its new kinds. Version 7 (`project/v7.rs`, [decision 0049](../../docs/decisions/0049-slit.md)) adds slits to version 6's operations (`OperationV7::V6`): 2 to 256 points, every number real, an eye whose flat-view direction isn't zero. Version 8 (`project/v8.rs`, [decision 0050](../../docs/decisions/0050-pipe-bends.md)) adds bent extrudes (`OperationV8::V7` for the rest): every number real, the bend brought into range. Version 9 (`project/v9.rs`, [decision 0051](../../docs/decisions/0051-connect-bridge-weld.md)) adds Connect, Bridge and Weld. Version 10 (`project/v10.rs`, [decision 0052](../../docs/decisions/0052-clean-up.md)) adds the clean-up edits: deleted and dissolved elements (`ElementsV10`), filled holes, flipped polygons and Fix normals (`FixFacing`). Version 11 (`project/v11.rs`, [decision 0053](../../docs/decisions/0053-hard-and-soft-edges.md)) adds hard and soft edges (an edge must join two different points) and hard edges by angle (a real angle, brought within 0–180°). Version 12 (`project/v12.rs`, [decision 0055](../../docs/decisions/0055-basics.md)) is `ProjectWithInstances<E>`: version 5's model plus `InstanceV12` (object, source), each instance written in the object list as a group; `OperationV12::V11` holds version 11's edits. Version 13 (`project/v13.rs`) adds slid points (`OperationV13::SlidePoints`: a real amount, never towards itself) to version 12's file. Version 14 (`project/v14.rs`, [decision 0059](../../docs/decisions/0059-symmetry-for-every-edit.md)) adds mirrored edits (`OperationV14::Mirrored`: a version 13 edit that can be mirrored, the axes, at least one on, a real middle, and the clip switch) and the middle welded once (`OperationV14::WeldMiddle`: the axes, a real middle and a distance of 0 or more); they don't nest. Version 15 (`project/v15.rs`, [decision 0062](../../docs/decisions/0062-spirals.md)) stores every bent extrude with its whole bend (`ExtrudeBentV15`, `BendV15`: angle, direction, radius, segments, rise and the mirrored flag; every number real, the bend brought into range), on its own (`OperationV15::ExtrudeBent`) or mirrored (`MirroredBent`: axes, at least one on, a real middle, clip); `OperationV15::V14` holds the rest. Version 16 (`project/v16.rs`, [decision 0068](../../docs/decisions/0068-pivot-editing-and-scene-units.md)) is `ProjectWithPlaces<E>` (`ProjectV16` with `EntryV15`): version 15's file as it was (`ProjectWithInstances<E>`), plus `OffsetV16` for each object whose shape doesn't sit on its pivot (real numbers, not flattened, an object that is there, listed once) and the project's units (`UnitsV16`); older files open with every shape on its pivot, in metres. `ProjectWithInstances::into_document_with` lets a later version attach its own per-object data. Version 17 (`project/v17.rs`, [decision 0070](../../docs/decisions/0070-extrude-freedom.md)) is `ProjectWithPlaces<EntryV17>`: extrudes shaped the first way are stored as version 15 stores them (`OperationV17::V15`, and version 3 stores only those), others with their whole shape (`ExtrudeV17`: direction, end size, steps, flat end; real numbers checked, settings brought into range), on their own (`Extrude`) or mirrored (`MirroredExtrude`); extrudes from older files open as `ExtrudeShape::EARLIER`. Version 18 (`project/v18.rs`, [decision 0074](../../docs/decisions/0074-material-slots.md)) is `ProjectV18`: version 17's file (`ProjectWithPlaces<EntryV18>`) plus `MaterialsV18` for each object with materials (at most 64, names not empty, colours 0 to 1, an object that is there, listed once; attached through `ProjectWithPlaces::into_document_with`), and `OperationV18`: version 17's edits as they were (`V17`) and polygons given a material slot (`SetMaterialV18`: a slot under 64), on their own (`SetMaterial`) or mirrored (`MirroredSetMaterial`); older files open with no materials. Version 19 (`project/v19.rs`, [decision 0076](../../docs/decisions/0076-engine-export-paths.md)) is `ProjectV19`: version 18's file plus the game project folder (`TargetV19`: folder and on-save switch, checked with `ExportTarget::is_valid`); older files open with none. Version 20 (`project/v20.rs`, [decision 0078](../../docs/decisions/0078-kit-export.md)) is `ProjectV20`: version 19's file plus each object's collision shape (`CollisionV20`; an object that is there, listed once; attached through `ProjectV19::into_document_with`). Versions 18 to 20 are generic over the edits they store (`ProjectV18<E>`, `ProjectV19<E>`, `ProjectV20<E>`, standing for `EntryV18` unless given), so a later version can change only its edits. Version 21 (`project/v21.rs`, [decision 0081](../../docs/decisions/0081-bends-keep-their-shape-on-stretched-objects.md)) is `ProjectV21` (`ProjectV20<EntryV21>`): `OperationV21` stores a bend made on a stretched object with its stretch (`StretchedBent`, `MirroredStretchedBent`: the version 15 bend and a stretch above 0 and at most 1000 on each axis, checked with `mesh::extrude::usable_stretch`), and everything else as version 18 to 20 did (`V18`); older writers refuse a stretched bend rather than drop the stretch, and older files open with no stretch. Version 22 (`project/v22.rs`, [decision 0082](../../docs/decisions/0082-edits-keep-their-shape-on-stretched-objects.md)) is `ProjectV22` (`ProjectV20<EntryV22>`): `OperationV22::Stretched` stores any edit with a stretch as version 21 stores it without one, beside the stretch (checked with `mesh::stretch::usable`; refused on an edit that can't keep one, or one stored with two), and everything else as version 21 did (`V21`). Version 23 (`project/v23.rs`, [decision 0085](../../docs/decisions/0085-bevel-control.md)) is `ProjectV23` (`ProjectV20<EntryV23>`): `OperationV23::Bevel` stores a bevel of edges with any of its further settings as version 22 stores it without them, beside `BevelOptionsV23` (checked against `BevelOptions::clamped`; refused on an edit that isn't a bevel of edges), and everything else as version 22 did (`V22`); version 4's writer only takes bevels with none of them. Version 24 (`project/v24.rs`, [decision 0086](../../docs/decisions/0086-groove.md)) is `ProjectV24`: `OperationV24::Groove` and `MirroredGroove` store a groove (`GrooveV24`: edges, width, depth, sloped, stretch, anchors; width and depth checked, the width kept to `MAX_GROOVE_WIDTH`), and everything else as version 23 did (`V23`); older versions refuse a groove. Version 25 (`project/v25.rs`, [decision 0088](../../docs/decisions/0088-live-mirror.md)) is `ProjectV25`: version 24's file (`ProjectV20<EntryV24>`, its `into_document_with` letting later versions attach) and each object's live mirror (`MirrorV25`: object, axes, centre, weld distance; checked with `LiveMirror::is_valid`, refused twice, for an unknown object or one without a shape). Version 26 (`project/v26.rs`, [decision 0089](../../docs/decisions/0089-apply-transforms.md)) is `ProjectV26` (`ProjectV25<EntryV26>`): `OperationV26::PlaceShape` stores an applied placement's matrix (16 numbers, checked to be real and not flattening), and everything else as version 24 did (`V24`). Version 27 (`project/v27.rs`, [decision 0090](../../docs/decisions/0090-stable-element-names.md)) is `ProjectV27`: version 26's file (`ProjectV25<EntryV26>`, which now also has `into_document_with`) and each edit's anchored points' stable names (`NamesV27`: object, edit id, names; one per anchored point, never 0, for edits and objects that are there, never twice). Version 28 (`project/v28.rs`, [decision 0097](../../docs/decisions/0097-editing-uvs-by-hand.md)) is `ProjectV28` (`ProjectV27<EntryV28>`; version 27 is now generic over its entries): `OperationV28::TransformUvs` stores UVs moved by hand (polygons, points, six real numbers, anchors), and everything else as version 26 did (`V26`). Version 29 (`project/v29.rs`, [decision 0098](../../docs/decisions/0098-seams.md)) is `ProjectV29` (`ProjectV27<EntryV29>`): `OperationV29::SetSeams` and `MirroredSetSeams` store seams marked or cleared (edges as two different point ids, anchors; a mirror on at least one axis with a real middle), and everything else as version 28 did (`V28`). Version 30 (`project/v30.rs`, [decision 0099](../../docs/decisions/0099-unwrap-relax-straighten.md)) is `ProjectV30`: `OperationV30::Unwrap` (polygons, the strips switch, anchors), `StraightenUvs` and `RelaxUvs`, and everything else as version 29 did (`V29`). Version 31 (`project/v31.rs`, [decision 0100](../../docs/decisions/0100-texture-size-and-texel-density.md)) is `ProjectV31`: version 27's model with `OperationV31` edits (`SetTexelDensity`: polygons, a real density above 0, anchors; the rest as version 30) and the texture settings (`TextureV31`, checked with `TextureSettings::is_valid`); older files open with the standard settings. Version 32 (`project/v32.rs`, [decision 0101](../../docs/decisions/0101-packing.md)) is `ProjectV31<EntryV32>`: `OperationV32::PackUvs` (each island's polygon ids and six real numbers), and everything else as version 31 did (`V31`). Version 33 (`project/v33.rs`, [decision 0106](../../docs/decisions/0106-trim-sheets.md)) is `ProjectV33`: version 31's model (with `EntryV33`) and the trim sheet's rows (`RowV33`: name, bottom, top; checked with `TrimSheet::is_valid`), and `OperationV33::PlaceOnTrim` (polygons, a row's bottom and top within 0 to 1, anchors), the rest as version 32 (`V32`); older files open with no trim sheet. Version 34 ([decision 0109](../../docs/decisions/0109-pins-and-unwrap-methods.md)) is version 33's model with `EntryV34`: `OperationV34::SetUvPins` (polygons, points, pin or unpin, anchors) and `OperationV34::Unwrap` for unwraps that choose a method (`MethodV34`) or unfold one way (`AxisV34`); plain unwraps are still stored as version 30's, the rest as version 33 (`V33`). Version 35 ([decision 0110](../../docs/decisions/0110-controllable-automation.md)) is `ProjectV35`: version 33's model with `EntryV35` and the project's mending settings (`MendingV35`, checked with `MendOptions::is_real`; older files get the standard), with `OperationV35::Unwrap` (every `UnwrapOptions` choice: strip angle and where cuts hide, `HideV35`) and `OperationV35::RelaxUvs` (its steps), both checked with `numbers_are_real`; edits older versions can store are stored their way (`V34`). All thirty-five versions are read; version 35 is written, and a sample of each is kept in `tests/data`. **Exports** (`export`, `obj`, [decision 0071](../../docs/decisions/0071-obj-export-and-import.md)): Exports use each object's shown shape (`Scene::shown_shape`, with its live mirror). `summary(document, &ExportOptions)` counts what an export would hold (objects, triangles, materials by name) without making the file, for the Export window ([decision 0087](../../docs/decisions/0087-one-look-for-every-window.md)), and matches the written file's `ExportSummary`. `prepare(document, &ExportOptions)` gives each shown shape (or the selection and what is inside it) as an `ExportedObject`: its world shape and its shape around its pivot (`ExportMesh`: points once, distinct normals and UVs once, polygons whose `ExportCorner`s name a point, a normal and a UV), in the file's `FileUnits` and `UpAxis` (`ExportOptions::to_file`), shaded with `ExportOptions::hardness`, cut into triangles with `triangulate`, mirrored placements run backwards. Each `ExportPolygon` carries its material slot and each `ExportedObject` its `materials` (an instance its original's; a slot past the last is 0); `file_materials` lists the materials used, each name once, and `file_material` finds a polygon's ([decision 0074](../../docs/decisions/0074-material-slots.md)). **Kits** ([decision 0078](../../docs/decisions/0078-kit-export.md)): `export::prepare_piece` prepares one piece (an object and what's inside it, its pivot moved to the origin), `export::write_files` writes prepared objects in a format, and `engine::export_kit` writes each piece into a folder as its own file (`file_stem_for` names it; same names numbered; the same checks as `export_into`). `ExportOptions::godot_names` (set by the Godot preset) makes `gltf::write_glb` add Godot's collision endings to node names (`-col`, `-convcol`) and a `-convcolonly` box node. **Game projects** (`engine`, [decision 0076](../../docs/decisions/0076-engine-export-paths.md)): `detect(folder)` finds the `Engine` (Godot, Unity, Unreal Engine) and its project folder from the folder or one above it; `may_replace(path, app_name)` says whether a file is missing or was written by the app (an OBJ/MTL first line, or a glTF `generator`, naming it); `export_into` exports a document into an existing folder, named after the project, with a preset, checking every file before writing any (`TargetError`: no folder, not ours, the export's own error). `ExportPreset` (`Godot`, `Unity`, `UnrealEngine`, `SubstancePainter`; [decision 0075](../../docs/decisions/0075-export-presets.md)) gives each preset's name, description and `PresetSettings` (format, units, up axis, triangles). `export_bytes` gives `ExportFiles` (the file asked for, files beside it such as an OBJ's `.mtl`, and an `ExportSummary` with objects, triangles and materials), or `ExportError::Nothing`; `export_to` writes them all. `gltf::write_glb` writes binary glTF ([decision 0072](../../docs/decisions/0072-gltf-export.md)): a node per object at its pivot (a `matrix` unless at the origin), a mesh of its local shape (`gltf::vertices`: one vertex per distinct point, normal and UV, UVs turned to glTF's V-down, triangles per material slot), one material per name used (its colour as `baseColorFactor`, converted to linear), buffer views aligned to 4, MikkTSpace tangents (`TANGENT`, [decision 0073](../../docs/decisions/0073-mikktspace-tangents.md), `bevy_mikktspace` on the UVs as the file holds them) for shapes with UVs, vertices split where tangents differ, the JSON written with `serde_json`; `ExportFormat::Glb` (the standard) fixes metres, Y up and triangles (`ExportFormat::options`). `obj::write_obj` writes OBJ (a generator comment, a `# Units:` note, `mtllib` and a `usemtl` line at each change of material, names made one word) and `obj::write_mtl` its `.mtl` file (`newmtl`, `Kd`); `obj::read_obj` reads it (any index form; other lines skipped and counted, broken polygons left out and counted, unreal numbers refused, limits held), one plain mesh per `o` (or `g`) object, hard where the file's normals break, UVs into `mesh::attributes::UV`, `usemtl` names into each object's materials (in order of first use, at most 64) and slots; `read_mtl` reads a `.mtl` file's colours, `ObjImport::colour_materials` and `colour_from_files` (looked for beside the OBJ, by file name only) apply them; `noted_units` reads this app's note. Tests in `export/tests.rs` and `obj/tests.rs` (round trips, files from elsewhere, random text). **Saves that always reopen** ([decision 0041](../../docs/decisions/0041-saves-that-always-reopen.md)): `to_bytes` reads its own bytes back with `from_bytes` and fails with `ProjectError::WouldNotReopen` (also when an edit can't be stored), so neither `save` nor autosave copies ever hand out a project that won't open; `save` then keeps the old file and writes the bytes to `name.avtl.unreadable`. `safe_write` (a new uniquely named temporary file, never following links, synced, read back, renamed over the target, folder synced) is used for the project, its `.bak` and autosave copies.
- Reading checks everything, with plain-language `ProjectError`s (`NotAProject`, `TooNew`, `Damaged` naming the object, `TooLarge`, `Io`). **The limits rulebook** (`limits`, [decision 0045](../../docs/decisions/0045-limits-for-files.md)): the body is capped at 512 MB packed and unpacked (`MAX_UNPACKED`; a zstd body that states a larger size is refused before unpacking); every list in the file model is a `Bounded` list, saved like a plain one, whose items are paid for from a 2 GB budget (`MAX_MEMORY`) while the file is read, so a list can't claim more memory than allowed (`within`, `within_budget`, `limit_hit`, and the plain message `TOO_MUCH`); and `ProjectFile::check_limits` refuses more than `MAX_OBJECTS` objects, `MAX_EDITS` edits or about `MAX_POLYGONS` polygons (primitives estimated with `Primitive::polygon_estimate`) before anything is built. Positions, rotations and moves must be real numbers; meshes go through `Mesh::from_slots`, the tree through `Scene::from_objects`; primitive settings are clamped.
- `save` writes `name.avtl.tmp`, syncs it and reads it back, copies the previous save to `name.avtl.bak` (`backup_path`), then renames the new file into place.

Tests:
- round trips of a scene using every feature (byte-identical on resave);
- the header;
- refusals of other files, newer versions, unknown flags, cut and padded files and bad values;
- clamping;
- fuzzing every cut, 3000 random bit flips and random bodies, and 150 well-formed files with random nonsense inside (every shape that opens also worked out, each within seconds);
- the limits: too many objects, edits or polygons refused with the limit named and at once, bodies unpacking to too much (with and without their size stated) refused, and a read stopping when its memory budget runs out; bounded lists saving like plain ones and refusing lists that claim too much;
- saving on disk (backup, no leftovers, failure leaving the old file, unwritable folders, missing files);
- an ignored heavy-mesh check timing saving and opening a project with a 3-million-polygon shape (`tools/heavy/heavy-check.sh`);
- `tests/data/sample-v1.avtl` and `sample-v2.avtl`, files of each version that must open in every future version (`WRITE_SAMPLE=1` writes only the current version's).

**Backup copies** (`autosave`, [decision 0036](../../docs/decisions/0036-autosave.md)):

- `Session::start` makes a `session-<time>-<process>-<n>` folder inside the autosave folder and keeps its `lock` file locked (`File::try_lock`) while the app runs; the system lets go of the lock when the process ends in any way, a crash included.
- `Session::set_project` notes the open project in `project.txt`. `write`/`write_copy_in` write `copy-N.avtl` (written beside its name, synced, then renamed) and delete the oldest beyond the number kept (at least one). `adopt` copies a restored copy into the new session, keeping its time. `end` deletes the folder (a normal close).
- `leftovers` lists the sessions whose lock can be taken (no longer running) with their copies, newest first, and tidies away dead sessions without copies; `discard` deletes one. A session folder without its lock file is left alone for its first minute (an app may be starting). Backup folders are made readable only by their owner on Linux and macOS.
- `mark_restoring` notes in a leftover's folder which copy is being restored, and `clear_restoring` removes the note once the restore finishes; a note still there at the next start leaves that copy out (`Leftover::left_out`), so a copy whose restore closed the app isn't offered again (decision 0045).

Tests: numbering and keeping the newest, a running session versus a crashed one, order and the untitled case, tidying and ignoring other files, adopting (with its time) and two sessions side by side.

Export arrives in Phase 5.
