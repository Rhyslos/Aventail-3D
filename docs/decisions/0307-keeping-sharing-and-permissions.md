## Problem

Milestone 5 of scripting. A script must be able to travel with a project, and be shared as a file of its own, without a project or a shared file becoming a way to run someone else's code on your computer unasked. A project's scripts must not run, even to read their commands, until the person opening it turns them on; your own projects should remember that you did. A script must reach no files unless it asks for one of the three permissions (read the project folder; read and write it; read and write a folder you choose) and you allow it, once per script, being asked again when a later version asks for more. `Project:readText`, `writeText` and `exportShapes` need those permissions, and every trick with paths (`..`, whole paths, links out of the folder, very long names) must be refused.

## Options

1. **Where a project's scripts live:** (a) in the project file (the plan's file format bump), changed by a command so undo works; (b) in a folder beside the project file (a project would no longer be one file).
2. **How trust is remembered:** (a) by the project file's path (a moved project forgets; a file replaced at the same path would inherit trust); (b) by each script's **fingerprint** (the SHA-256 of its text): you trust exactly that code, wherever it is, and any change is asked about again.
3. **When permissions are asked for:** (a) only in the script manager (runs fail until allowed); (b) when a script whose header asks for something not yet allowed is run, in a window naming what it asks, with Allow and run and Don't run, the manager also allowing and taking back.
4. **When written files are written:** (a) at once (a script that fails later leaves files half done); (b) held until the run ends well, then each written whole, before the run's scene changes land.
5. **How paths are checked:** a script names files from inside its folder; everything else refused before any file is touched, and what's on disk checked again for links when writing.

## Decision

- **In the project file** (1a): `scene::ProjectScript` (file name and text), kept on the scene (`Scene::scripts`, shared, so copies cost nothing) and changed only with `Command::SetScripts` (one undo step; a list that isn't valid is refused: at most 64 scripts of 1 MB, names ending in `.lsc` or `.lua` without folders or characters a file can't hold, no two alike). Project file format **113** (`fileio::project::v113`; 112 is sculpting's) stores them; a damaged or hostile list (a name with a folder or drive, too big, twice) refuses the file with a reason. Older files open with none. Nothing in them runs while a project opens.
- **Shown, not edited:** the Scripts panel lists them under **In this project**; double-click shows one read-only, coloured, with line numbers (choice 47). Right-click: **Look at it**, **Run** (once on), **Turn on this project's scripts**, **Copy to your library**, **Export…**, **Take out of this project** (one undo step). A library script's right-click menu gains **Keep with this project** (a copy kept there; kept again, it's updated) and **Export…**.
- **Trust by fingerprint** (2b; choice 48): `script::fingerprint`, kept in the settings (`ScriptSettings::trusted`, at most 1,000). Until a project's scripts are trusted they aren't read at all: no commands, no run. A bar under the menu bar says "This project has 2 scripts. They won't run until you turn them on." with **Look at them**, **Turn them on** and **Not now** (choice 57). Keeping your own script with a project trusts it, so your own projects open with their scripts on. A trusted project script's commands join the Scripts menu and command search (named "(this project's)" when one of yours has the name), with settings in Attributes, but get no palette places or keys (choice 56).
- **Asked when run** (3b; choice 49): approvals are kept in the settings by script (`ScriptId`: your library's by file name, following renames; a project's by fingerprint; a file run from elsewhere by its path). A run whose header asks for anything not yet allowed opens **"… asks to reach files"** first, listing what it asks; **Allow and run** keeps the approval and runs it, **Don't run it** runs nothing. A script asking for a chosen folder picks it there (**Choose…**), kept with the approval; such a script reaches only that folder (choice 50). The script manager shows each script's asks with **Allow…** or **Take back**, its project scripts too. The console line reaches nothing. A run may reach only what its header asks for and was allowed (`script::Access`); a call reaching further is refused naming the `-- asks:` line to add.
- **Written at the end** (4b; choice 51): `script::access::Writes` holds what a run writes (at most 1,000 files and 256 MB); a read of a file the run wrote reads that. When the run ends well each file is written whole (`fileio::project::safe_write`), folders made as needed, before its scene changes land; a run that fails, is stopped or runs out of time writes nothing. Reads are at most 16 MB of UTF-8 text.
- **Paths** (5; choice 52): written from inside the folder with `/` or `\`. Refused: `..`, a path from the top of the computer, any `:` (drive letters, Windows' hidden streams), a link anywhere along the way (even one staying inside), names Windows keeps (`CON`, `NUL`, `COM1`…) or can't hold (`<>"|?*`, a trailing dot or space, control characters), names over 255 bytes, paths over 1,024 bytes or 32 folders deep. What's found on disk is checked again to be inside the folder, and again when writing.
- **`exportShapes(shapes, path, preset)`** (choice 53): the shapes (and what's inside groups among them, if shown) as they are in the run's copy, exported as the Export window does with the preset (`Preset`: Godot, Unity, UnrealEngine, Solis, SubstancePainter, Printing), its files beside (an OBJ's `.mtl`, textures) next to it; the path must end in the preset's ending. It gives nothing back (LustScript would make every call keep a value).
- **Sharing as single files:** **Scripts → Install a script…** shows the script's name, what it's about, its scripting version, what it asks for and its code before anything happens; **Install it** adds it to your library with a number added when the name is taken (choice 54), allowing nothing. **Scripts → Export a script** lists yours and the project's; each is saved as a file of its own (choice 55).

## Consequences

- A project with scripts can be shared safely: opening it runs nothing, and turning its scripts on still lets none reach files unasked.
- Trust and approvals live on one computer, in the settings; a script edited by one character is a different script to trust.
- A project script is changed by copying it into your library, editing it, and keeping it with the project again.
- One new dependency, `sha2` (MIT or Apache-2.0), for the fingerprint.
- File format 113. No new keys; new mouse actions only in the Scripts panel's list (right-click and double-click on the project's scripts).
