# 0292. The library browser

- **Status:** Accepted
- **Date:** 2026-11-13
- **Follows:** [0269](0269-material-extras.md) (the material extras), [0263](0263-your-own-boxes.md) (your own boxes and your library), [0264](0264-starter-graphs.md) (starter graphs and graph files), [0029](0029-selection.md) (Ctrl adds, Shift takes away), [0028](0028-ask-about-controls.md) (asking about controls)

## Problem

Phase 12's last extra (milestone 29, [decision 0269](0269-material-extras.md)): "one browser for all graphs and own boxes, with pictures, tags and search, and packs shared as one file". Until now graphs, own boxes and starters each had their own place: the graph list on the canvas bar, the shelf's two tabs (own boxes of the project and your library), and the Starter graphs window. Your library held only own boxes; a graph could not be kept for other projects, and graph files (`.matgraph`, milestone 8) had no button to write or read them. Nothing could be tagged or searched, and sharing a set of materials meant one file per box.

## Options

- **Where it lives.** (a) A new panel or shelf tab: the shelf is short, and the Material layout has no room for another panel beside the canvas and preview. (b) **A window opened from the canvas bar's Library button** (chosen), like the Starter graphs window: big enough for cards with pictures, out of the way when closed. The shelf and the Starter graphs window stay as they are (quick ways in that milestones 7 and 8 built and the manual teaches).
- **What it lists.** Everything, in three groups: **This project** (its graphs and own boxes), **Your library** (kept with the app's settings, in every project: own boxes as before, and now **graphs too**) and **Starter graphs**. A **Show** choice (graphs and own boxes, graphs, own boxes) and a **From** choice (everywhere, or one group) narrow it.
- **Tags.** (a) Tags only in your library, kept beside the files. (b) **Tags on graphs and own boxes themselves** (chosen), so they are saved with the project, travel in graph files, box files and packs, and the project's cards can be tagged too. Tags are tidied, not refused: lower case, single spaces, at most 32 letters and 12 tags, no repeats, sorted (`matgraph::tags`). A starter's tags are fixed (set in `fileio::starter_graphs`, translated as other words are). A box that differs from the project's only in its tags is the same box when brought in (`OwnBox::same_but_tags`), so tagging never makes duplicates.
- **Search.** Every word typed must be in the card's name or one of its tags, in any order and case: "stone floor" finds Stone tiles and Cobbles. **Clicking a tag** in the row of tags in use shows only cards with it (several clicked: cards with all of them); clicking it again stops.
- **Controls** (no new keys; [decision 0028](0028-ask-about-controls.md)): a **click** chooses a card, **Ctrl + click** chooses more, **Shift + click** takes one away (the app's own rule, decision 0029), and a **double-click** opens it, as the plan named. Dragging a card onto the canvas was considered and left: the plan didn't name it, and double-click or **Place it** does the same.
- **Opening.** A project graph is shown; a library graph or starter opens **as a copy** in the project (one undo step, named with a number when the name is taken, its own boxes brought in beside it); an own box is **placed** on the graph shown, as the shelf does.
- **Packs.** (a) Several files zipped together: needs a zip dependency and an unzip step a person can get wrong. (b) **One readable JSON file, `.matpack`** (chosen): each graph stored as a graph file stores it (with the own boxes it uses) and each own box as a box file stores it (with the boxes inside), so every entry reads exactly as its own file would, and an entry never depends on another. A box two entries share is stored twice; packs are small, and that keeps each entry whole. **Export as a pack…** writes the chosen cards (starters are left out: they come with the app); **Bring in…** reads a pack, a graph file or a box file into your library, all of it or nothing (a damaged entry refuses the whole pack, naming it), replacing graphs by name and boxes by id, and the window then shows your library.
- **Pictures.** Starters and own boxes bring their pictures. A graph's card is worked out small (128 pixels, shown at 96) on a thread of its own, one graph at a time, using one core so the canvas's pictures come first; it is kept and made again only when that graph changes (the scene gives a changed graph a new `Arc`), never while scrolling or searching, and not while a button is held down. Until a new picture comes, the card keeps its old one.
- **Left for later.** Dragging a card onto the canvas or a shape. Folders or groups inside your library (tags do that job for now). A picture for a graph kept in your library that is saved with it (it is worked out again each session, in the background). A pack format version above 1 for packs holding newer things: a pack carries graph files' own versions inside, and the reader reads every version this app knows.

## Decision

- `matgraph::tags` (`tidy_tag`, `tidy_tags`, `are_tidy`, `matches`, `MAX_TAGS` 12, `MAX_TAG` 32); `Graph::tags`, `GraphParts::tags`, `GraphEdit::SetTags` ("Change the graph's tags"); `OwnBox::tags`, `OwnParts::tags`, `OwnBox::same_but_tags` (used by bringing boxes in, `GraphFile::fitted_to` and placing from your library).
- **File format 110** (`fileio::project::v110`): tags on each graph (`GraphV95::tags`) and own box (`OwnBoxV98::tags`), stored only when there are some, tidied when read. **Graph and box files format 6** when anything holds tags (still 1 without). **Packs** (`fileio::pack_file`: `Pack`, `write_pack`, `read_pack`, `.matpack`, at most 64 MB and 256 entries, format 1), fuzz-tested.
- `ui::material::library` (the window, `Browser`, `ItemId`, `LibraryGraph`, `MaterialEditor::library_graphs`, `keep_graph`, `keep_box`, `set_item_tags`, `chosen_pack`), `library_pictures` (`CardPictures`). `MaterialEditor::open_graph_file` (shared with the starters) copies any graph file into the project as one undo step.
- Your library's graphs are kept with the app's settings under `library_graphs` (graph files' text), shared by every tab. Workbench: `pack_file`, `pack_saved`, `bring_into_library`, `graph_library`, `with_graph_library`; actions `SavePack` and `BringIntoLibrary`.
- **No new keys or mouse actions** beyond click, Ctrl / Shift + click and double-click.

## Consequences

Every graph and own box is one window away, found by name or tag, and a set of them goes to another computer or person as one file. Graphs can now be kept for every project, which was the missing half of your library. Tags add a little to project, graph and box files only when used, so files without tags open in older apps as before. Graphs kept in your library live in the app's settings file, so a library of many graphs holding photos makes that file large; the 256-graph limit and each graph file's own 16 MB limit bound it.
