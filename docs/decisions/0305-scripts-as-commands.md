## Problem

Milestone 4 of scripting: a script's commands (a LustScript `component` with a `run()`, or Lua's `command(…)` with a `run` function) become the app's own commands. They must show in a Scripts menu and command search, with their settings in Attributes; changing a setting runs the command again in place as one undo step; a count setting gets Ctrl + wheel. A script manager lists your scripts, turns them off or on, renames, removes and reloads them. A command can go on the command palette or get a key of its own, a key already taken being refused with the name of what uses it. The time and memory limits move into Settings → Scripts. All of this must survive a restart, and reading a script's commands must never run anything outside the sandbox or hold up the app.

## Options

1. **Finding a script's commands:** (a) read them from the text (a Lust component's fields can be read without running, a Lua table can't); (b) run the script's start once, in a fresh sandbox against an empty scene, as the plan's "Describe" step says, and read what it made.
2. **Running one command with chosen settings:** (a) write the settings into the script's text before running; (b) run the start, make the command, set its fields from the chosen values (those that still fit its kind), then call its `run`.
3. **Changing a setting in Attributes:** (a) keep the run and change only what differs (scripts can't say what differs); (b) take the last run back (`Document::undo`), run again with the new settings, the newest change winning: a run under way is stopped and started again with the newest; a run that fails does the last good one again (`Document::redo`), so a typo in a setting never loses the result.
4. **Where keys and palette places are kept:** (a) in the script's header; (b) in the app's settings (the plan's choice: no keys as standard, Give it a key… on a command).

## Decision

- **Described by running the start** (1b): `script::commands_of(file, names, limits)` gives the header, the commands (name, words, settings with their kind and starting value) and the script's mistakes and notes, from a fresh sandbox with an empty scene, at most `DESCRIBE_LIMIT` (2 s), nothing it does landing. LustScript fields come from Lust's own `__schema` (bool, int, float, string, a state's options, vec3, colour; other kinds are kept but not shown); Lua settings by their starting value's kind, a whole number being a whole-number setting (choice 38), listed by name (choice 40). At most 64 commands a script and 64 settings a command. A Lua setting named `run` or starting with `__` is left out with a note; two Lua commands of one name keep the first, with a note.
- **One command, settings set on it** (2b): `Run::start_command(file, snapshot, limits, names, Choice)`. A setting the script no longer has, or a value of the wrong kind, keeps the script's start; a command no longer in the script is a mistake saying so.
- **The app reads the library on a thread of its own** (`ui::script_commands::Registry`): every 2 s it looks at each file's size and time, and reads again only those that changed. A script with mistakes has no commands until it's mended (the manager says why); a script that makes no commands is one command of its own, running the whole file (choice 39). Commands are named by the script's header (`-- name:`) when it makes one, as "Script: Command words" when it makes several, and two with the same name are told apart by their files.
- **Shown everywhere commands are:** the **Scripts** menu lists them under **Script manager…**, with their keys; **command search** (Space) finds them under "Scripts", with their `about`; commands put on the **command palette** sit after its own groups, each a page-with-brackets icon (`Icon::Script`, our own drawing), a right click taking it off.
- **Settings in Attributes, again in place** (3b): while a command's run is the last thing done (no change, undo, selection or element selection since, as a tool's Last edit, decision 0120; choice 46), its settings show first in Attributes, by their names in words; changing one runs it again as described, still one undo step, and a run that fails brings the last good one back with its settings (choice 45). **Ctrl + wheel** changes the setting the header's `-- count:` names, from 1 to 1,000, while it shows (the viewport's wheel goes to it before a tool's count; choice 43).
- **Kept in the app's settings** (4b, `ScriptSettings`, saved as `scripts`): the time limit (1 s to 10 min) and memory limit (32 MB to 2 GB, choice 42), the palette's commands, the keys, the scripts turned off and each command's settings as last used; checked into range on reading, so a damaged file gives usable values; shared by every tab (`take_shared_from`). Keys are kept by their names (`F6`).
- **Keys:** right-click a script in the Scripts panel's list → **Give it a key…** (or the manager's button) opens a window that takes the next key pressed, with Ctrl, Shift or Alt. A key the app uses anywhere (every entry of the Keys window's list), Esc, Enter, Tab and Backspace on their own, or one another script command has, is refused naming what uses it (choice 41). A command's key runs it when nothing is typed and no window is open.
- **The script manager** (Scripts → Script manager…): each script with its name, file, `about`, what it asks for, its mistakes or notes, an **On** switch (off: its commands leave the menus, search, palette and keys, but it still runs from the panel), its commands with **Give it a key…** and **On the command palette**, and **Edit**, **Reload**, **Rename…**, **Remove…** (asked first; the file is deleted, choice 44) and **Show in its folder**. Renaming keeps its keys, palette places and settings (`Library::rename`, `ScriptSettings::renamed`).
- **Versions:** a script for a newer scripting version gives no commands and is refused when run; one for an older version would run with a note (version 1 is the only one so far).

## Consequences

- A script you write shows up as a command within two seconds of saving it, with no restart, and its settings behave like a built-in tool's.
- Reading every script's start costs a fresh sandbox per changed file on a background thread; a script whose start takes longer than 2 s has no commands (the manager says to move slow work into `run`).
- Changing a setting reruns the whole command; a slow command reruns once dragging stops (each change stops the run before).
- A Lua decimal setting must start at a number with decimals (`width = 0.5`), or it's taken as a whole number (choice 38).
- No new file format (111). No new keys as standard; new mouse actions: right-click a script command (palette button, list entry) for its menu.
